When checking work against REQUIREMENTS.md / the brief (MATCH REQ, MIMS), ask **what the line is for**, then whether the product meets that purpose anywhere sensible, before demanding it on a specific screen.

Example: "host replies shown on listing" (SOW) means replies are public next to their review for anyone viewing the experience. The All reviews page, reached from the listing, meets it; it does not require replies on the long experience page itself.

**Why:** I flagged a "Must" gap by reading "on listing" literally and nearly pushed clutter back onto a page the user had just simplified (2026-11-27). The user wants briefs read for intent.

**How to apply:** for each requirement, state the purpose in one line, check where it is satisfied, and only raise a gap if the purpose isn't met anywhere reasonable. If the wording is genuinely ambiguous and the choice matters, say so in one line instead of insisting. Related: [[cptr]], [[mims]], [[dupe]].
